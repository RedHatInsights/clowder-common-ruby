# clowder-common-ruby

## Project Overview

A Ruby gem that reads the JSON configuration file written by the [Clowder][clowder] operator and
exposes it as typed Ruby objects. Provides convenience accessors for Kafka, database, object storage,
and other subsystems. Published to [RubyGems.org][rubygems] under the Apache-2.0 license. Includes
optional Rails engine integration that injects config into `Settings` at boot.

## Dependencies

- **Runtime:** Ruby (3.4.9, pinned in `.ruby-version`), `ostruct` (~> 0.6.3). Rails (~> 8.1) is
  optional, required only for the engine/initializer integration.
- **Dev/test:** `rake` (~> 13.4), `rspec` (~> 3.13), `rspec-rails` (~> 8.0),
  `climate_control` (~> 1.2).

## Architecture

All runtime classes live under the `ClowderCommonRuby` module. `Config` (hand-written) extends
`AppConfig` (auto-generated from upstream JSON Schema) and provides the public API: `load`,
`clowder_enabled?`, and five convenience accessors. Sixteen type classes in `types.rb` mirror the
upstream schema definitions, each extending `OpenStruct`. See [ARCHITECTURE.md][architecture] for
the full design analysis, code generation pipeline, and dependency points.

## Development Commands

See [Development Setup][readme-dev] in the README for the full command reference.

Commands relevant to agent-driven workflows:

```sh
# Regenerate types.rb from upstream Clowder JSON Schema
./sync_config.sh

# Run tests (CI runs this same command)
ACG_CONFIG="test.json" bundle exec rake spec

# Build the gem
bundle exec rake build

# Bump patch version (used by schema.yml CI workflow)
ruby bin/bump_version
```

CI (`package.yml`) runs `bundle exec rake spec` with `ACG_CONFIG=test.json`. The `deploy.yml`
workflow publishes the gem via `bundle exec rake release` when `version.rb` changes on `master`.

## Code Style

No linter or formatter is configured. No RuboCop, Standard, or `.editorconfig` is present. No
linting step exists in any CI workflow.

Property names in generated type classes use camelCase (matching the JSON schema keys directly),
not Ruby snake_case convention.

## Common Mistakes

1. **Editing `types.rb` by hand.** This file is auto-generated by `bin/json_schema_ruby` from
   `bin/schema.json`. Manual edits will be overwritten when `sync_config.sh` runs. To change type
   behavior, edit `bin/ruby_class_converter.rb` instead, then regenerate.

2. **Forgetting `ACG_CONFIG` when running tests.** Tests require the `ACG_CONFIG` environment
   variable to point to a valid JSON config file. Without it, `Config.load` will fail. Use
   `ACG_CONFIG="test.json" bundle exec rake spec`.

3. **Assuming snake_case property accessors.** All config accessors use camelCase names from the
   JSON schema (e.g., `config.publicPort`, `config.database.hostname`, `broker.secretAccessKey`),
   not Ruby-idiomatic snake_case. Only the five hand-written convenience methods on `Config` use
   snake_case (`kafka_topics`, `kafka_servers`, `object_buckets`, `dependency_endpoints`,
   `private_dependency_endpoints`).

4. **Adding runtime dependencies to the gemspec.** The gemspec intentionally declares zero runtime
   dependencies. All dependencies are in the Gemfile. Adding `add_dependency` to the gemspec would
   change the install behavior for all consumers.

5. **Confusing `AppConfig` with `Config`.** `AppConfig` is the auto-generated base class in
   `types.rb`. `Config` in `config.rb` is the hand-written subclass that provides the public API.
   Always use `ClowderCommonRuby::Config.load`, not `AppConfig.new`.

## Testing

RSpec with 5 examples in `spec/config_spec.rb` covering `kafka_topics`, `object_buckets`,
`dependency_endpoints`, `private_dependency_endpoints`, and `kafka_servers`. The `.rspec` file
sets `--color --order random`. CI uses the same test command as local development.

## Deployment

The `deploy.yml` workflow checks if `lib/clowder-common-ruby/version.rb` changed in the latest
push to `master`. If yes, it runs `bundle exec rake release` to publish the gem to RubyGems.org
using the `GEM_HOST_API_KEY` secret. Version bumps are typically automated by the `schema.yml`
workflow when upstream schema changes are detected.
